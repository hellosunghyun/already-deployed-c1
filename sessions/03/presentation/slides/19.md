# Slide 19. Inspect는 원인을 찾는 도구입니다

화면 문제는 보통 CSS에서 시작합니다.

Inspect로 확인할 것:

```text
선택한 요소의 class
font-size
line-height
margin / padding
gap
max-width
display grid / flex
```

Codex에게 바로 고치게 하기 전, 먼저 원인 후보를 말하게 합니다.

<details><summary>슬라이드 모습과 강조점</summary>

**슬라이드 모습**

- 핵심 문장을 크게 보여줍니다.
- 코드블록은 참가자가 그대로 따라 쓸 수 있는 형태로 둡니다.
- 시각적 예시는 말로 길게 설명하지 않고, 실습에서 브라우저 화면을 보며 연결합니다.

**강조해야 하는 내용**

- 디자인 수정은 감상평이 아니라 구체적 요구사항입니다.
- Codex에게 바로 실행시키기보다 먼저 원인 후보와 최소 수정 계획을 받습니다.
- 모바일과 build 검증까지가 하나의 수정 단위입니다.

</details>

<details><summary>발표자 노트</summary>

초보자에게 DevTools 전체를 가르치지 않습니다. 선택한 요소의 class와 적용된 CSS 정도만 보게 합니다.

</details>
