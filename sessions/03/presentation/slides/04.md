# Slide 04. 성공 기준은 세 단계입니다

## 최상

Codex 브라우저 주석으로 2개 이상 영역을 지정하고, 데스크톱과 모바일에서 수정 결과를 검증합니다.

## 표준

스크린샷 또는 브라우저 / Browser 주석으로 한 영역을 정확히 지정하고, 작은 CSS 수정 후 build까지 확인합니다.

## 최소

현재 화면, 고치고 싶은 영역, 문제 설명, 다음 요청 프롬프트가 남습니다.

---

오늘의 핵심은 **선택, 요청, 검증**입니다.

<details><summary>슬라이드 모습과 강조점</summary>

**슬라이드 모습**

- 핵심 문장을 크게 보여줍니다.
- 코드블록은 참가자가 그대로 따라 쓸 수 있는 형태로 둡니다.
- 시각적 예시는 말로 길게 설명하지 않고, 실습에서 브라우저 화면을 보며 연결합니다.

**강조해야 하는 내용**

- 디자인 수정은 감상평이 아니라 구체적 요구사항입니다.
- Codex에게 바로 실행시키기보다 먼저 원인 후보와 최소 수정 계획을 받습니다.
- 모바일과 build 검증까지가 하나의 수정 단위입니다.

</details>

<details><summary>발표자 노트</summary>

수정 결과의 미적 수준보다 수정 요청의 정확성을 성공 기준에 둡니다. 최소 성공도 충분히 의미 있다고 안내합니다.

</details>
