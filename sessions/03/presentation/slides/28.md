# Slide 28. 이제 워크북으로 갑니다

워크북에서는 각자 화면을 기준으로 진행합니다.

오늘 실습 중 질문할 때는 아래를 함께 남깁니다.

```text
URL
Viewport
선택한 영역
문제 설명
원하는 방향
유지할 것
수정 후 확인 결과
```

끝까지 못 해도 좋습니다.

**정확한 디자인 요청 1개**가 남으면 다음 세션으로 이어갈 수 있습니다.

<details><summary>슬라이드 모습과 강조점</summary>

**슬라이드 모습**

- 핵심 문장을 크게 보여줍니다.
- 코드블록은 참가자가 그대로 따라 쓸 수 있는 형태로 둡니다.
- 시각적 예시는 말로 길게 설명하지 않고, 실습에서 브라우저 화면을 보며 연결합니다.

**강조해야 하는 내용**

- 디자인 수정은 감상평이 아니라 구체적 요구사항입니다.
- Codex에게 바로 실행시키기보다 먼저 원인 후보와 최소 수정 계획을 받습니다.
- 모바일과 build 검증까지가 하나의 수정 단위입니다.

</details>

<details><summary>발표자 노트</summary>

발표를 마무리하고 실습으로 이동합니다. 참가자가 각자 다른 화면을 갖고 있어도 같은 요청 구조를 쓰면 진행 가능하다는 점을 강조합니다.

</details>
