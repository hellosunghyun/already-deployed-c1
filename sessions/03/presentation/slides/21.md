# Slide 21. 나쁜 요청과 좋은 요청

나쁜 요청:

```text
Projects가 좀 별로야. 세련되게 해줘.
```

좋은 요청:

```text
/projects의 첫 번째 카드 영역을 봐줘.
390px 모바일에서 카드 제목, 설명, 도구 태그가 모두 비슷하게 보여서 읽는 순서가 약해.
색은 유지하고 제목 굵기, 설명 줄 간격, 태그 크기만 조정하는 계획을 먼저 제안해줘.
```

좋은 요청은 AI가 수정 범위를 추측하지 않게 합니다.

**슬라이드 모습**

- 핵심 문장을 크게 보여줍니다.
- 코드블록은 참가자가 그대로 따라 쓸 수 있는 형태로 둡니다.
- 시각적 예시는 말로 길게 설명하지 않고, 실습에서 브라우저 화면을 보며 연결합니다.

**강조해야 하는 내용**

- 디자인 수정은 감상평이 아니라 구체적 요구사항입니다.
- Codex에게 바로 실행시키기보다 먼저 원인 후보와 최소 수정 계획을 받습니다.
- 모바일과 build 검증까지가 하나의 수정 단위입니다.
