# Slide 10. Codex Browser의 제약도 알아야 합니다

Codex in-app browser는 로컬 개발 서버와 로그인 없는 페이지에 적합합니다.

주의할 점:

- 로그인 페이지나 쿠키가 필요한 작업에는 한계가 있음
- 일반 Chrome 프로필이나 확장 프로그램을 그대로 쓰지 않음
- 민감한 정보는 브라우저 흐름에 넣지 않음
- 더 깊은 디버깅은 Developer mode / CDP 승인이 필요할 수 있음

도구가 할 수 있는 일과 못 하는 일을 구분합니다.

<details><summary>슬라이드 모습과 강조점</summary>

**슬라이드 모습**

- 핵심 문장을 크게 보여줍니다.
- 코드블록은 참가자가 그대로 따라 쓸 수 있는 형태로 둡니다.
- 시각적 예시는 말로 길게 설명하지 않고, 실습에서 브라우저 화면을 보며 연결합니다.

**강조해야 하는 내용**

- 디자인 수정은 감상평이 아니라 구체적 요구사항입니다.
- Codex에게 바로 실행시키기보다 먼저 원인 후보와 최소 수정 계획을 받습니다.
- 모바일과 build 검증까지가 하나의 수정 단위입니다.

</details>

<details><summary>발표자 노트</summary>

3회차에서는 주로 localhost를 다루므로 in-app browser가 적합합니다. 로그인이나 민감한 사이트 이야기가 나오면 Chrome extension과 승인 흐름으로 분리합니다.

</details>
