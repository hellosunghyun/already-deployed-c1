# 배포했는데요? 1기 — 3회차 자료

이 폴더는 **3회차 수업을 Markdown 문서만으로 진행하기 위한 자료 묶음**입니다.
1회차는 배포 루프를 만들었고, 2회차는 Home / About / Projects / Posts 구조를 만들었습니다.
3회차에서는 그 화면을 보며 **AI에게 디자인 수정과 요구사항을 정확히 전달하는 법**을 훈련합니다.

## 오늘의 목표

**스크린샷, 브라우저 주석, 선택한 화면 영역, 모바일 확인 결과를 근거로 Codex에게 디자인 수정을 요청합니다.**

오늘의 핵심은 "예쁘게 해줘"가 아닙니다. 화면을 막연히 예쁘게 만드는 수업이 아닙니다.
아래처럼 구체적인 디자인 피드백을 만드는 수업입니다.

```text
URL: /projects
Viewport: 390x844 모바일
Target: 첫 번째 프로젝트 카드 제목과 설명 영역
Problem: 제목과 설명의 위계가 약하고 카드 사이 간격이 좁아 보임
Direction: 제목은 조금 더 굵게, 설명은 줄 길이를 줄이고 카드 간격을 키우기
Constraint: 새 라이브러리 추가 금지, 전체 색상 톤은 유지, 카드 데이터 구조 변경 금지
Verification: Codex Browser에서 모바일 폭 확인 후 npm run build
```

## 3회차에서 다루는 것

- 스크린샷을 AI에게 줄 때 빠뜨리면 안 되는 정보
- Codex in-app browser로 로컬 화면 확인하기
- Codex browser comments로 특정 요소/영역에 주석 달기
- `@Browser`를 이용해 렌더링 화면, 선택 영역, 모바일 폭을 확인시키기
- 좋은 디자인 수정 요청의 6좌표
- Reference를 그대로 복사하지 않고 분해해서 요구사항으로 바꾸기
- getdesign.md, Refero Styles, designmd.app 같은 DESIGN.md 레퍼런스 참고하기
- 다른 홈페이지를 레퍼런스로 잡고, GPT에게 디자인 토큰을 설명하게 하기
- 레퍼런스 토큰을 내 홈페이지용 CSS 변수와 수정 지시로 번역하기
- Home hero, Navigation, Projects 카드, Posts 목록의 시각 위계 개선
- 모바일 화면에서 제목, 카드, Navigation, 여백이 깨지는지 확인
- 색 대비, focus 상태, 링크/버튼 크기 같은 접근성 기본 점검
- 변경 후 브라우저 확인, `npm run build`, commit / push / deploy 확인

## 2시간 운영안

3회차는 **발표 30분 + 실습 90분** 기준입니다.
다만 3회차는 디자인 완성도가 사람마다 크게 달라질 수 있으므로, 모든 참가자가 같은 화면을 만드는 것이 목표가 아닙니다.

| 시간 | 구간 | 목표 |
|---|---|---|
| 0:00-0:05 | 시작과 2회차 상태 확인 | 2회차 구조와 현재 URL 상태 확인 |
| 0:05-0:15 | 좋은 디자인 요청 설명 | 스크린샷, 주석, 6좌표 피드백 이해 |
| 0:15-0:22 | Codex Browser 설명 | in-app browser, comments, Browser use, 제약 이해 |
| 0:22-0:30 | 데모 | 레퍼런스 홈페이지를 디자인 토큰으로 분해하고 Home hero에 작게 적용 요청 |
| 0:30-0:45 | 실습 01-03 | 현재 화면 baseline, 스크린샷 피드백 작성 |
| 0:45-1:00 | 실습 04-06 | Codex Browser 주석, 레퍼런스 토큰 브리프, 수정 backlog 만들기 |
| 1:00-1:25 | 실습 07-09 | Home / Navigation / Projects / Posts 중 1~2개 영역 수정 |
| 1:25-1:42 | 실습 10-11 | 모바일 확인, 접근성 polish |
| 1:42-1:52 | 실습 12-13 | 브라우저 검증, build, commit / push |
| 1:52-2:00 | 실습 14 | 결과 기록, before/after, 4회차 준비 |

## 오늘의 성공 기준

### 최상

- Codex Browser에서 화면 영역에 주석을 달고 수정 요청을 했다.
- Home hero, Projects 카드, Navigation, Posts 목록 중 2개 이상을 개선했다.
- 모바일 폭 390px / 768px / 데스크톱 폭에서 확인했다.
- `npm run build`가 성공했고 GitHub Pages에 반영했다.
- before/after 기록이 남았다.

### 표준

- 스크린샷 또는 Browser 주석을 근거로 한 영역을 정확히 지정했다.
- 하나의 디자인 문제를 작은 CSS 수정으로 해결했다.
- 모바일 화면에서 크게 깨지지 않는지 확인했다.
- build 성공 또는 실패 로그가 있다.

### 최소

- 현재 화면 스크린샷, 고치고 싶은 영역, 문제 설명, 다음 요청 프롬프트가 남았다.
- Codex가 어디를 고쳐야 하는지 알 수 있는 피드백 1개를 만들었다.
- build를 못 했더라도 현재 상태와 막힌 지점을 기록했다.

## 진행자가 기억할 기준

3회차는 참가자가 "디자인 감"이 없다고 느끼기 쉬운 회차입니다. 진행자는 미감 평가보다 **관찰 가능한 문제**로 바꿔줍니다.

| 막연한 말 | 관찰 가능한 말 |
|---|---|
| 예쁘게 해줘 | 제목과 설명의 크기 차이를 키워줘 |
| 뭔가 답답해 | 섹션 위아래 여백과 카드 간격을 비교해줘 |
| 모바일이 이상해 | 390px 폭에서 Navigation이 두 줄로 깨지고 첫 제목이 4줄이 됨 |
| 더 세련되게 | 색은 유지하고 border, shadow, spacing만 정리해줘 |
| 레퍼런스처럼 | 레퍼런스의 전체가 아니라 색 역할, 글자 위계, 카드 간격 같은 토큰만 가져와줘 |


## 레퍼런스 토큰 적용 흐름

3회차에는 레퍼런스를 단순히 링크로 붙이지 않습니다. 아래 순서로 **디자인 언어를 토큰화**한 뒤 Codex에게 적용시킵니다.

```text
1. 마음에 드는 홈페이지 1개 선택
2. GPT에게 레퍼런스의 디자인 토큰 설명 요청
3. 색, 타이포그래피, 여백, radius, shadow, layout width로 분해
4. 원하는 요소 1개만 선택하고, 가져올 토큰과 버릴 토큰을 나누기
5. CSS custom properties 또는 기존 global.css 변수에 매핑
6. Codex에게 특정 영역에만 적용 요청
7. Codex Browser에서 before/after와 모바일 확인
```

여기서 중요한 것은 **레퍼런스 전체 복제 금지**입니다. 브랜드 고유 색, 로고, 이미지, 복잡한 인터랙션을 그대로 옮기지 않고, 내 사이트에 맞는 역할 토큰만 가져옵니다.

## 참고 가능한 레퍼런스 사이트

3회차에서는 일반 홈페이지 URL뿐 아니라 아래 DESIGN.md 레퍼런스 사이트도 참고합니다.

| 사이트 | 수업에서의 역할 |
|---|---|
| [getdesign.md](https://getdesign.md/) | 브랜드/제품 스타일을 DESIGN.md 분석으로 훑고 방향성을 고릅니다. |
| [Refero Styles](https://styles.refero.design/) | 실제 제품 화면 기반 AI-readable style을 보고 원하는 요소를 고릅니다. |
| [designmd.app](https://designmd.app/) | DESIGN.md 형식과 ready-made design system을 참고합니다. |

레퍼런스를 고른 뒤에는 전체를 따라 하지 않고 아래처럼 원하는 요소 하나만 가져옵니다.

```text
가져올 것: hero title scale / project card framing / posts list density / color role 중 하나
버릴 것: 브랜드 고유 이미지, 로고, 전체 색상 복제, 무거운 animation, 외부 font
적용 위치: 내 홈페이지의 URL + viewport + target으로 지정
```
