# 14. 결과 기록과 4회차 준비

## 목표

3회차 디자인 수정 결과와 다음에 이어갈 질문을 기록합니다.

## 왜 하는가

3회차는 화면을 보며 수정하는 회차입니다.
무엇을 어떻게 고쳤는지, 무엇이 아직 남았는지 기록하지 않으면 4회차에서 외부 콘텐츠 소스를 붙일 때 화면 기준을 잃습니다.

## 결과 기록 폼

```text
GitHub 저장소 URL:
GitHub Pages URL:
수정한 페이지:
수정한 영역:
사용한 레퍼런스 URL:
사용한 디자인 토큰:
수정 전 문제:
수정 방향:
수정한 파일:
브라우저 확인 결과:
모바일 확인 결과:
build 결과:
commit 메시지:
남은 문제:
다음에 이어서 보낼 프롬프트:
```

## before / after 기록

가능하면 수정 전후 스크린샷을 남깁니다.

```text
Before:
- URL:
- Viewport:
- 문제:

After:
- 바뀐 점:
- 좋아진 점:
- 아직 아쉬운 점:
```

## Codex에게 결과 요약 요청

```text
3회차 디자인 수정 결과를 다음 세션에서 이어갈 수 있게 요약해줘.

아래 형식으로 정리해줘.

1. 오늘 수정한 페이지와 영역
2. 수정 전 문제
3. 실제 변경한 파일
4. 사용한 레퍼런스와 디자인 토큰
5. 디자인 방향에서 유지한 것
6. desktop 확인 결과
7. mobile 확인 결과
8. 접근성 확인 결과
9. build / deploy 확인 결과
10. 아직 남은 문제
11. 다음에 내가 Codex에게 이어서 보낼 수 있는 프롬프트

중요:
- 실제 확인한 내용만 써줘.
- 실패한 것이 있으면 실패했다고 정확히 써줘.
- 과장하지 마.
```

## AGENTS.md 갱신 프롬프트

시간이 있으면 3회차에서 배운 화면 검증 규칙을 `AGENTS.md`에 반영합니다.

```text
현재 프로젝트의 AGENTS.md에 3회차 디자인 수정 규칙을 추가하고 싶어.

반영할 규칙:
- 디자인 수정은 화면 전체가 아니라 특정 URL, viewport, target을 기준으로 한다.
- 레퍼런스는 그대로 복제하지 않고 color, typography, spacing, radius, shadow, layout 토큰으로 분해해서 사용한다.
- Codex Browser에서 로컬 화면을 확인하고, 가능하면 browser comments를 기준으로 수정한다.
- 수정 전에는 원인 후보와 최소 수정 계획을 먼저 설명한다.
- 새 라이브러리, 외부 폰트, 큰 구조 변경은 사용자 승인 없이 하지 않는다.
- 디자인 수정 후 desktop과 390px mobile에서 확인한다.
- 가능하면 npm run build로 검증한다.
- commit과 push는 변경사항 요약 후 사용자 승인 뒤 진행한다.

작업 방식:
- 아직 수정하지 마.
- 먼저 현재 AGENTS.md와 비교해서 추가할 문장만 제안해줘.
- 너무 길게 만들지 말고 꼭 필요한 규칙만 남겨줘.
```

## 4회차 준비

4회차에서는 외부 콘텐츠 소스를 연결합니다.
3회차 결과를 기준으로 아래를 준비합니다.

```text
Posts에 실제로 넣고 싶은 글 3개
Projects에 실제로 넣고 싶은 프로젝트 3개
외부 콘텐츠 소스로 쓸 후보: Notion / Markdown / JSON 유지
콘텐츠가 들어와도 유지하고 싶은 디자인 기준
모바일에서 반드시 유지해야 할 구조
```

## 체크박스

- [ ] GitHub 저장소 URL을 기록했다.
- [ ] GitHub Pages URL을 기록했다.
- [ ] 수정한 페이지와 영역을 기록했다.
- [ ] 사용한 레퍼런스 URL과 디자인 토큰을 기록했다.
- [ ] before / after를 기록했다.
- [ ] 모바일 확인 결과를 기록했다.
- [ ] build 성공 또는 실패 로그를 기록했다.
- [ ] commit 메시지를 기록했다.
- [ ] 남은 문제를 적었다.
- [ ] 다음에 이어서 보낼 프롬프트를 만들었다.
- [ ] 4회차 콘텐츠 준비 항목을 확인했다.

## Ready Gate

오늘 마무리 전에 아래가 되어 있으면 충분합니다.

- 정확한 디자인 수정 요청 1개 이상이 남았습니다.
- 레퍼런스를 사용했다면 어떤 토큰을 가져왔고 무엇을 버렸는지 기록했습니다.
- 수정한 결과 또는 실패 로그가 기록되어 있습니다.
- 모바일 확인 결과가 있습니다.
- 다음 세션에서 이어갈 수 있는 프롬프트가 있습니다.

## 마무리 문장

오늘 만든 것은 완성된 디자인이 아닙니다.
하지만 이제 화면을 보고 AI에게 정확히 요청하는 방법을 갖게 되었습니다.

```text
1회차: 인터넷에 올라가는 첫 버전
2회차: 읽히는 정보 구조
3회차: 화면의 특정 요소/영역을 짚어 디자인 수정
4회차: 외부 콘텐츠 소스 연결
5회차: 운영 가능한 홈페이지로 정리
```
