# 11. 접근성 polish: 대비, focus, 터치 영역

## 목표

디자인 수정 결과가 읽기 쉽고 조작 가능한지 기본 접근성 관점에서 점검합니다.

## 왜 하는가

좋아 보이는 화면도 글자 대비가 낮거나 focus 상태가 보이지 않거나 링크가 너무 작으면 실제 사용성이 나빠집니다.
3회차에서는 접근성을 깊게 다루지는 않지만, 디자인 수정에서 꼭 지켜야 할 기본 기준을 확인합니다.

## 오늘 확인할 것

```text
본문 텍스트 대비
링크와 버튼 대비
hover / focus 상태
키보드 Tab 이동 시 focus가 보이는지
모바일 터치 영역이 너무 작지 않은지
텍스트가 너무 작지 않은지
```

## Codex에게 보낼 프롬프트

```text
3회차 디자인 수정 결과를 접근성 기본 기준으로 점검하고 싶어.

대상:
- /, /about, /projects, /posts
- desktop과 390px mobile

확인할 것:
1. 본문 텍스트가 배경과 충분히 대비되는지
2. 링크와 버튼이 클릭 가능한 요소처럼 보이는지
3. hover와 focus-visible 스타일이 있는지
4. 키보드 Tab 이동 시 현재 focus 위치가 보이는지
5. 모바일에서 링크나 버튼 터치 영역이 너무 작지 않은지
6. 글자 크기가 너무 작거나 줄 간격이 답답하지 않은지

수정 방향:
- 색상 팔레트 전체를 바꾸지 않고 필요한 대비만 보강
- focus-visible은 명확하게 보이게
- 버튼/링크 padding은 모바일에서 충분하게
- 새 라이브러리 없이 CSS로 해결

중요:
- 자동 점검만 믿지 말고 화면에서 사람이 볼 때의 문제도 함께 말해줘.
- 아직 수정하지 말고 문제 목록과 최소 수정 계획을 먼저 제안해줘.
```

## Lighthouse 선택 확인

시간이 남으면 Chrome DevTools Lighthouse 또는 Codex가 가능한 방식으로 accessibility audit을 확인합니다.

```text
가능하면 Lighthouse 접근성 점검을 실행하거나, 실행 방법을 알려줘.
점수가 목표가 아니라 실패 항목이 있는지 확인하고, 3회차 범위 안에서 바로 고칠 수 있는 것만 골라줘.
```

## 체크박스

- [ ] 본문 텍스트 대비를 확인했다.
- [ ] 링크와 버튼이 구분되는지 확인했다.
- [ ] focus-visible 상태를 확인했다.
- [ ] Tab 이동 시 focus가 보이는지 확인했다.
- [ ] 모바일 터치 영역을 확인했다.
- [ ] 필요한 최소 CSS 수정만 했다.

## Ready Gate

다음 단계로 넘어가기 전에 아래가 되어 있어야 합니다.

- 읽기 어려운 색 대비 문제가 줄었습니다.
- 키보드 focus가 최소한 보입니다.
- 모바일에서 주요 링크가 너무 작지 않습니다.
