# 00. 워크북 사용법

## 목표

2회차 결과를 보존하면서 3회차의 `관찰 → 계획 → 승인 → 수정 → 검증 → 기록` 흐름을 이해합니다.

## 왜 하는가

3회차는 새 홈페이지를 만드는 수업이 아닙니다. 기존 화면을 보지 않고 바로 CSS를 고치면 이미 잘된 부분이나 배포 설정까지 바꿀 수 있습니다.

이번 회차에서는 먼저 증거를 모으고, 디자인 백로그 `D-001` 하나만 승인해서 실행합니다.

## 쉬운 설명

이 워크북의 각 파일은 **하나의 실습 단계**입니다.

- **목표**: 이 단계가 끝나면 무엇이 생기는가
- **왜 하는가**: 다음 단계 전에 왜 필요한가
- **쉬운 설명**: 처음 보는 단어를 짧게 풀어 설명
- **AI에게 보낼 프롬프트**: 그대로 복사해 사용할 문장
- **체크박스**: 내가 실제로 했는지 확인
- **Ready Gate**: 다음 단계로 넘어가도 되는지 확인
- **힌트**: 막혔을 때 순서대로 확인할 내용
- **퀴즈**: 헷갈릴 수 있는 개념 확인
- **저장 체크포인트**: 다음 단계에 넘길 값을 기록

## 오늘의 전체 흐름

```text
2회차 레포와 숙제 회수
→ 실행 상태와 정확한 Local URL 확인
→ Browser 또는 스크린샷으로 수정 전 증거 기록
→ 레퍼런스에서 요소 하나 선택
→ Home / Navigation / Projects·Posts 중 챌린지 하나 선택
→ Plan mode에서 최종 수정 계획 확인
→ docs/design-backlog/D-001.md 작성
→ 사용자 승인
→ D-001 하나만 수정
→ 같은 URL과 viewport로 다시 확인
→ build / 배포 / 결과 기록
```

## 오늘 계속 지킬 규칙

```text
- 새 프로젝트를 만들지 않는다.
- 기존 2회차 레포와 가능하면 기존 Codex 채팅에서 이어간다.
- 터미널이 출력한 정확한 Local URL을 사용한다.
- 화면과 레퍼런스, 챌린지 선택이 끝난 뒤 Plan mode를 사용한다.
- 최종 Plan을 승인한 뒤 D-001 하나로 기록한다.
- 사용자가 승인한 D-001 하나만 수정한다.
- 새 라이브러리와 배포 설정 변경은 별도 승인 없이 진행하지 않는다.
- 수정 전후에 같은 URL과 viewport를 사용한다.
```

## Plan mode와 구현 모드

Plan mode는 Codex가 바로 파일을 고치지 않고 맥락, 위험, 작업 순서를 정리하는 모드입니다.

```text
/plan
```

또는 지원되는 Codex 앱에서는 `Shift + Tab`으로 모드를 전환할 수 있습니다.

이번 회차의 Plan mode는 Browser baseline, 6좌표, 레퍼런스 토큰, 챌린지 선택이 모두 준비된 뒤 사용합니다. 최종 계획을 확인하고 승인한 다음 09단계에서 `D-001`로 기록합니다. 파일을 만들거나 수정하기 전에는 Plan mode 표시가 꺼진 구현 모드인지 확인합니다.

자세한 복사 프롬프트는 [Plan mode 프롬프트 모음](../templates/plan-mode-prompts.md)을 참고합니다.

## Browser 사용 기준

Codex에서 사용하는 공식 태그 이름은 `@Browser`입니다. `@Browser`가 자동완성되지 않거나 현재 환경에서 Browser를 지원하지 않으면 일반 브라우저 스크린샷을 첨부하는 경로로 진행합니다.

Browser 권장 설정은 아래와 같습니다.

```text
브라우저: 켬
주석 스크린샷: 항상 포함
승인: 나 대신 승인
```

화면 예시는 [Browser 설정 스크린샷](../assets/codex-browser-settings.png)을 참고합니다.

`나 대신 승인`은 수업 중 로컬 화면 확인을 빠르게 하기 위한 기본값입니다. 비밀번호·token·secret 입력, 결제, 삭제, commit·push 같은 외부 변경은 Browser에 자동으로 맡기지 않고 각 단계의 사용자 승인 절차를 따릅니다.

## 막혔을 때 AI에게 보낼 프롬프트

[막혔을 때 질문 템플릿](../templates/stuck-question-template.md)에 현재 단계, 정확한 Local URL, viewport, 실행한 명령과 오류를 채웁니다.

```text
나는 3회차 워크북의 [단계 이름] 단계에 있어.
새 프로젝트가 아니라 기존 2회차 Astro 홈페이지를 이어서 작업 중이야.

현재 상태:
- 정확한 Local URL:
- Target과 viewport:
- 방금 한 일:
- 오류 또는 이상한 화면:

제약:
- 새 라이브러리는 추가하지 마.
- 관련 없는 파일과 배포 설정은 수정하지 마.
- 아직 수정하지 말고 원인 후보와 다음 한 단계만 제안해줘.
```

## 체크박스

- [ ] 새 프로젝트가 아니라 2회차 레포를 이어서 사용한다.
- [ ] 화면 증거와 레퍼런스를 모은 뒤 02단계에서 최종 Plan을 받는다는 것을 이해했다.
- [ ] 공식 Browser 태그가 `@Browser`라는 것을 확인했다.
- [ ] Browser를 못 쓰면 스크린샷으로 대체할 수 있다는 것을 안다.
- [ ] D-001 하나만 승인하고 실행한다.

## Ready Gate

- 전체 실습 순서와 중단 조건을 설명할 수 있습니다.
- 실행 전 사용자 승인과 수정 후 검증이 각각 필요하다는 것을 알고 있습니다.
- 아직 프로젝트 파일을 수정하지 않았습니다.

## 퀴즈

### 질문

3회차에서 코드를 수정하기 전에 반드시 준비해야 하는 것은?

- A. 새 Astro 프로젝트
- B. 가장 인기 있는 UI 라이브러리
- C. 화면 증거와 D-001, 사용자의 실행 승인
- D. 전체 사이트를 바꾸는 요청

<details>
<summary>정답 보기</summary>

**정답: C**

화면 증거와 한 개의 백로그 항목을 기준으로 범위를 좁힌 뒤 승인해야 기존 결과를 지킬 수 있습니다.

</details>
