# 12. 브라우저와 build로 최종 검증

## 목표

3회차 디자인 수정 결과를 브라우저와 `npm run build`로 확인합니다.

## 왜 하는가

디자인 수정은 CSS 중심이라 쉽게 보이지만, import 오류, class 이름 실수, Astro build 오류가 생길 수 있습니다.
최종 검증 없이 commit하면 GitHub Pages에서 실패할 수 있습니다.

## Codex에게 보낼 프롬프트

```text
3회차 디자인 수정 결과를 최종 검증하고 싶어.

확인할 URL:
- /
- /about
- /projects
- /posts

확인할 viewport:
- 390x844
- 768x1024
- 1440x900

확인할 것:
1. 각 페이지가 열리는지
2. Navigation 링크가 동작하는지
3. Home hero 수정 결과
4. Projects 카드 또는 Posts 목록 수정 결과
5. 모바일에서 가로 스크롤이 없는지
6. focus-visible 스타일이 보이는지
7. 레퍼런스 토큰을 적용한 영역만 바뀌었는지
8. 수정 전보다 나빠진 부분이 있는지
9. npm run build 결과

중요:
- 문제가 있으면 바로 대규모 수정하지 마.
- 문제 목록을 먼저 만들고, 최소 수정만 제안해줘.
- build 오류가 있으면 오류 원인을 초보자도 이해할 수 있게 설명해줘.
```

## build 실패 시 프롬프트

```text
npm run build에서 아래 오류가 났어.

[오류 붙여넣기]

요청:
1. 오류 원인을 쉽게 설명해줘.
2. 어떤 파일이 문제인지 추정해줘.
3. 디자인 수정과 직접 관련된 오류인지 판단해줘.
4. 가장 작은 수정 계획을 먼저 제안해줘.
5. 내가 승인하면 수정해줘.
```

## 체크박스

- [ ] `/`가 열린다.
- [ ] `/about`이 열린다.
- [ ] `/projects`가 열린다.
- [ ] `/posts`가 열린다.
- [ ] Navigation 링크가 동작한다.
- [ ] 390px 모바일에서 확인했다.
- [ ] 레퍼런스 토큰 적용 범위가 너무 넓지 않은지 확인했다.
- [ ] `npm run build`를 실행했다.
- [ ] build 성공 또는 실패 로그를 기록했다.

## Ready Gate

다음 단계로 넘어가기 전에 아래가 되어 있어야 합니다.

- 브라우저 확인 결과가 있습니다.
- build 결과가 있습니다.
- 실패했다면 실패 로그와 다음 질문이 있습니다.
