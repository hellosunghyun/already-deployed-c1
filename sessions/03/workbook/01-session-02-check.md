# 01. 2회차 결과와 현재 화면 확인

## 목표

3회차 디자인 수정을 시작할 수 있는 기준 상태를 확인합니다.

## 왜 하는가

디자인 수정은 화면이 열려야 할 수 있습니다.
먼저 Home / About / Projects / Posts 중 어떤 페이지가 열리는지 확인해야 Codex에게 정확한 URL과 상태를 줄 수 있습니다.

## 확인할 것

```text
GitHub 저장소 URL:
GitHub Pages URL:
로컬 프로젝트 폴더 위치:
사용할 AI 도구: Codex
로컬 실행 주소:
열리는 페이지:
안 열리는 페이지:
2회차에서 만든 구조:
```

## Codex에게 보낼 프롬프트

```text
3회차 디자인 수정 작업을 시작하려고 해.
2회차에서 만든 Astro 개인 홈페이지를 이어서 작업하는 것이 목표야.

먼저 현재 상태를 확인해줘.

내가 알고 있는 정보:
- GitHub 저장소 URL: [입력]
- GitHub Pages URL: [입력, 없으면 없음]
- 로컬 프로젝트 폴더 위치: [입력]
- 사용하는 도구: Codex

확인해줬으면 하는 것:
1. 현재 작업 폴더가 Astro 프로젝트인지
2. package.json과 src/pages가 있는지
3. /, /about, /projects, /posts 페이지가 있는지
4. npm run dev로 로컬 실행 가능한지
5. Codex Browser에서 열 수 있는 URL이 무엇인지
6. 3회차에서 디자인 수정 전에 조심해야 할 파일이 무엇인지

중요:
- 아직 파일을 수정하지 마.
- 삭제나 reset 같은 위험한 명령은 실행하지 마.
- 먼저 어떤 명령어로 확인할지 계획을 설명해줘.
- 내가 승인하면 확인 명령어를 실행해줘.
```

## 승인 후 추가 프롬프트

```text
좋아. 방금 계획대로 상태 확인을 진행해줘.
확인 후 아래 형식으로 요약해줘.

1. 현재 프로젝트가 맞는지
2. 열리는 URL
3. 디자인 수정이 가능한 페이지
4. 먼저 고치면 좋은 화면 후보
5. 다음 단계로 넘어가도 되는지
```

## 체크박스

- [ ] 작업 폴더 위치를 확인했다.
- [ ] `package.json`이 있는지 확인했다.
- [ ] 로컬 개발 서버를 실행했다.
- [ ] Codex Browser에서 로컬 주소를 열었다.
- [ ] `/`, `/about`, `/projects`, `/posts` 중 열리는 페이지를 확인했다.
- [ ] 오늘 고칠 후보 화면을 1개 이상 정했다.

## Ready Gate

다음 단계로 넘어가기 전에 아래가 되어 있어야 합니다.

- 로컬 화면을 브라우저에서 볼 수 있습니다.
- 어떤 페이지를 고칠지 후보가 있습니다.
- Codex가 아직 파일을 수정하지 않았습니다.
