# 03. 스크린샷 기반 피드백 작성

## 목표

스크린샷을 Codex가 이해할 수 있는 디자인 수정 요청으로 바꿉니다.

## 왜 하는가

스크린샷만 보내면 AI는 화면 전체를 보고 추측합니다.
정확한 수정 요청에는 이미지와 텍스트 설명이 같이 필요합니다.

## 스크린샷 피드백의 6좌표

```text
URL:
Viewport:
Target:
Problem:
Direction:
Constraint:
```

## 스크린샷을 만들 때 포함할 것

- 브라우저 주소 또는 페이지 이름
- 데스크톱인지 모바일인지
- 고치고 싶은 영역 표시
- 문제를 한 문장으로 설명
- 유지할 스타일 또는 건드리지 말아야 할 파일

## Codex에게 보낼 프롬프트

```text
첨부한 스크린샷을 기준으로 디자인 피드백을 만들고 싶어.

먼저 스크린샷에서 아래를 파악해줘.

1. 이 화면에서 주요 콘텐츠 영역이 무엇인지
2. 내가 고치고 싶어 할 가능성이 높은 문제 후보
3. 수정하면 안 되는 영역 후보
4. 이 문제를 Codex에게 요청하기 위한 6좌표 피드백 초안

중요:
- 아직 파일을 수정하지 마.
- 스크린샷만 보고 확실하지 않은 것은 추측이라고 표시해줘.
- 화면 전체를 한 번에 바꾸자고 하지 말고, 가장 작은 수정 단위 1개를 제안해줘.
- 새 라이브러리는 제안하지 마.
```

## 사용자가 직접 채우는 양식

```text
URL:
Viewport:
Target:
Problem:
Direction:
Constraint:
Verification:
```

## 좋은 예시

```text
URL: /projects
Viewport: 1440x900 desktop
Target: Projects 카드 목록 전체
Problem: 카드 제목과 설명의 크기 차이가 약해서 한눈에 훑기 어렵다.
Direction: 제목은 조금 더 굵게, 설명은 조금 더 작고 옅게, 카드 사이 gap은 20~24px 정도로 정리한다.
Constraint: 프로젝트 JSON 구조는 유지한다. 새 라이브러리는 추가하지 않는다. 색상 팔레트 전체는 바꾸지 않는다.
Verification: Codex Browser에서 /projects 확인 후 390px 모바일도 확인한다.
```

## 체크박스

- [ ] 스크린샷을 준비했다.
- [ ] URL을 적었다.
- [ ] Viewport를 적었다.
- [ ] Target을 한 영역으로 좁혔다.
- [ ] Problem을 관찰 가능한 문장으로 적었다.
- [ ] Direction을 구체적으로 적었다.
- [ ] Constraint를 적었다.
