# 09. Projects 카드와 Posts 목록 시각 위계 개선

## 목표

Projects 카드와 Posts 목록을 더 읽기 쉬운 구조로 개선합니다.

## 왜 하는가

2회차에서 Projects와 Posts 구조를 만들었다면, 3회차에서는 그 구조가 실제로 읽히는지 확인해야 합니다.
데이터가 있어도 카드와 목록의 시각 위계가 약하면 방문자는 무엇을 봐야 할지 모릅니다.

## Projects 카드에서 확인할 것

- 제목이 가장 먼저 보이는가
- 설명과 역할이 구분되는가
- 도구 태그가 너무 강하거나 약하지 않은가
- 결과 또는 배운 점이 잘 읽히는가
- 자세히 보기 링크가 명확한가
- 모바일에서 카드가 답답하지 않은가

## Posts 목록에서 확인할 것

- 글 제목이 먼저 보이는가
- 날짜와 태그가 보조 정보처럼 보이는가
- 요약의 줄 길이가 적절한가
- 목록 사이 간격이 일정한가
- Projects 카드와 너무 똑같이 보이지 않는가


## 레퍼런스 요소를 쓰는 경우

Projects와 Posts에서는 레퍼런스 전체가 아니라 아래 요소 중 하나만 가져옵니다.

```text
Projects 추천:
- Project card framing
- Card gap / padding rhythm
- Tag와 metadata의 muted color 역할

Posts 추천:
- Posts list density
- 날짜, 태그, 제목, 요약의 위계
- 목록 사이 간격

가져오지 않을 것:
- 레퍼런스의 브랜드 색 전체 적용
- 아이콘/이미지/로고 복제
- 데이터 구조 변경
- 복잡한 hover animation
```

## Codex에게 보낼 프롬프트

```text
Projects 카드와 Posts 목록의 시각 위계를 개선하고 싶어.

대상:
- URL: /projects, /posts
- Viewport: desktop과 390px mobile
- Target: Projects 카드 목록, Posts 글 목록

현재 목표:
1. Projects는 사례 카드처럼 보이게 한다.
2. Posts는 글 목록처럼 보이게 한다.
3. 제목, 설명, 보조 정보의 위계가 분명해야 한다.
4. 모바일에서 카드와 목록이 답답하지 않아야 한다.

Projects 수정 방향:
- 카드 제목은 가장 강하게
- 설명은 읽기 쉽게
- role/tools/result는 보조 정보로 정리
- 자세히 보기 링크는 클릭 가능한 것처럼 보이게
- 카드 간격과 내부 padding 균형 맞추기

Posts 수정 방향:
- 글 제목을 우선
- 날짜와 태그는 보조 정보로
- 요약은 너무 긴 줄이 되지 않게
- 목록 간격을 일정하게

제약:
- projects.json과 posts.json 데이터 구조는 유지해.
- 외부 이미지나 아이콘 추가하지 마.
- 새 라이브러리 추가하지 마.
- 상세 페이지 구조를 크게 바꾸지 마.
- 아직 수정하지 말고, 먼저 문제 후보와 최소 수정 계획을 말해줘.
```

## 선택 실습

시간이 부족하면 둘 중 하나만 선택합니다.

```text
A. Projects 카드만 개선
B. Posts 목록만 개선
```

## 체크박스

- [ ] Projects 카드 제목과 설명 위계를 확인했다.
- [ ] Projects 카드 자세히 보기 링크가 보인다.
- [ ] Posts 제목과 보조 정보 위계를 확인했다.
- [ ] desktop과 mobile에서 확인했다.
- [ ] 데이터 JSON 구조를 유지했다.
- [ ] 새 라이브러리를 추가하지 않았다.

## Ready Gate

다음 단계로 넘어가기 전에 아래 중 하나 이상이 되어 있어야 합니다.

- Projects 카드가 더 훑기 쉬워졌습니다.
- Posts 목록이 글 목록처럼 보입니다.
- 아직 수정하지 못했다면 Projects / Posts 중 어느 쪽이 문제인지 기록했습니다.
